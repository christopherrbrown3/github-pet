# Beta 4 release-candidate QA checklist (issue #106, "Release candidate QA")

Prepared 2026-11-20 by QA from #106, `docs/updates.md`, the CI workflow and the Beta 3 evidence. **Not run.** It runs against the RC artifact, which exists only after #92, the hide-snooze/privacy/quiet-hours PRs (#94/#95/#107) and #109 are merged. Verdicts follow `acceptance-matrix.md` (PASS / FAIL / BLOCKED / NOT RUN); a check that needs real interaction and was not done is **NOT VERIFIED**, never PASS.

## Rules for the run

- **Exact artifact only.** The candidate is one `main` commit `<SHA>` and the `GitHubPet-app` artifact of one `workflow_dispatch` run of `Swift` on exactly that SHA (CI-built, tested, universal). Never a locally built ZIP, never a PR-run artifact.
- **No synthetic input** (clicks, keystrokes, CGEvent, `cliclick`, UI-driving AppleScript) on the real desktop. Use launch options, the scenario runner, offscreen renders and read-only commands. Interaction-only items are NOT VERIFIED or handed to Chris.
- **The production Sparkle key is off-limits** (no read, list, copy, hash or search of any `*.key`; never the default Keychain account). Only the public key is checked. Only `github-pet-qa` throwaway accounts exist, and only for the update-run QA agent.
- **Isolation constraint (important).** The RC artifact has the production bundle ID `dev.github-pet.GitHubPet`. `--defaults-suite` isolates the app's settings but **not Sparkle's own keys** (its prefs live in the bundle-ID domain), and a launched RC would start the updater against the live feed. So: (a) run **static checks** (R2-R5, R12) on the artifact; (b) run every **launched** check on a build of the same `<SHA>` made with `BUNDLE_ID_SUFFIX=.qa` (and `SPARKLE_FEED_URL=http://127.0.0.1:<port>/appcast.xml` served empty, so no live network) and say so in the report; (c) one real launch of the unmodified artifact (first install, Open Anyway) is Chris's, on his Mac, and is reported by Chris. If neither (b) nor (c) is possible, mark the item BLOCKED.
- Synthetic data only; no real account; gh is always a fake (`GITHUB_PET_GH_PATH`) or the tripwire. Do not delete preference plists; list every `qa-*` / `dev.github-pet.*` plist left behind for Chris.
- Evidence record: `<SHA>`, dispatch run ID + `headSha`, artifact name + SHA-256, macOS/arch, commands + exit codes, per ID PASS/FAIL/BLOCKED/NOT RUN/NOT VERIFIED, and an explicit "not verified" list.
